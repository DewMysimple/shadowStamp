# 系统架构

## 模块职责与边界

React提供语义按钮、面板、加载状态与错误回退，原生Three.js只有一个renderer和共享RAF。`config.js`定义八态ID/name/label/english/number/image及布局；`artwork.js`一次解码本地1254方形透明PNG，生成八种720×900票面Canvas，保留6×8半圆齿孔alpha。App等待解码再建立画廊，卸载有取消保护，启动读取最新参数；无WebGL使用同一Canvas转图片与配置布局。

印刷图稿是平面颜色，`SurfaceTexture.js`独立生成浅纸纹法线，不读取狮头高度。原有`paperLight`结合RGB光图、浅法线、主灯/橙灯，没有模式分支、金属或真实位移。2026-10-27去掉照明等待uBlur近零的门槛，光影与图稿回清晰同步渐入。完整RoomEnvironment/Neutral与原站专用资产不属于本地适配范围。

## 数据流与依赖

1. 用户图片只读复制到`public/assets/lion-states/`，八图SHA与E盘完整v2原件相同；本地加载，无运行时远程资源。
2. App读取JSON v2/appearanceRevision4参数，4组51字段；configure原地更新。本轮主题改动仅在CSS中调整参数面板与控件，不影响邮票、画廊底色或保存参数。参数预览默认焦点为STAMPS首项joy，不再硬编码craft。
3. 同一PerspectiveCamera生成GPU姿态与DOM命中，局部raycast UV驱动暖光。光图珊瑚/苔绿RGB和alpha经50采样散焦，mix桃橙底并默认.26 multiply；独立主灯/橙灯与浅纸纹保留。
4. 光学RT384×480、上限24fps；坐标密度为26.7/(lightScale*sizeNorm)，按票面尺寸/DPR更新uniform，不重分配纹理。活动票ID改变时setActiveStamp使光场dirty并当帧接管新目标UV，绕过持续流动节流；票内移动仍保留原缓动。textureScale独立控制纸纹。无活动输入收敛后停帧。
5. 八票为26张GPU纹理，hover/聚焦循环复用；dispose归0。其他票48tap加mipmap预滤波虚化，影子用持久alpha与24tap shader。

## 运行与部署

React19.2.8、Three0.185.1、Vite8.2.2；本机Node24.16、Chrome/Playwright。`npm run dev`默认4173；`npm run build`生成忽略的dist。无远程部署。本轮自建4280生产预览验收后已停止，用户开发服务保留。

`test:rapid-hover`为切卡时序和实际GPU像素验证，`test:stamps`为八态完整接入验证；原browser/light/controls/fidelity脚本已适配新ID/数量并写lion-stamps/regression。`capture-lion-stamps.mjs`重导出8PNG、总览与截图。

## 证据与未核实项

2026-10-27实际unit15、快速切卡6、browser14、production4和build通过，当前四源SHA与after报告一致。独立默认动态24次切换首帧owner/UV一致，旧票活动量单调渐出。材质只解除blur硬门槛、光场只改跨票时序，RGB公式/灯色/法线和参数默认保持。没有重复整套原站光学研究，不把旧6票20纹理或绿墨统计当当前证据。
