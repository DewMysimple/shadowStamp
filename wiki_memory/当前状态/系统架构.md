# 系统架构

## 模块职责与边界

React提供语义按钮、参数面板、三个系列筛选及静态回退。config.js提供12枚邮票数据、画幅和布局；artwork.js解码12张独立地域场景PNG，按45:65、60:45、40:75绘制票面Canvas。Three.js共享一个renderer和RAF，处理局部悬停暖光、票面偏转/虚化、聚焦与清理。浅纸纹使用独立法线，不从印刷图案提取高度；没有凸字、真实图案位移或金属化材质。

## 数据流与依赖

1. 页面读取STAMPS元数据与本地/assets/stamps/图像；每组四张通过筛选导航展现。输出PNG是静态印刷票面。
2. lightPresets.js定义六个稳定ID与GPU分支；StampMaterial.js提供旧乘算/新加光/滤色/柔光/指数漫照/亮度塑形，仅作用交互邮票，默认新版；桌面背景单独静态渲染。参数控件、存储与导入共享白名单合同。
3. DappledLight.js共用局部光图，旧版aspect固定.786，其他算法适配票面宽高比；纸纹scale独立于光图paintScale。每票预建17041/27041两种法线，切换不分配资源。
4. 鼠标、键盘、触摸命中共用DOM按钮和同一姿态；聚焦/返回切换阶段而不重新分配素材。无WebGL回退用平面票面与相同分组数据。
5. 本轮报告观察到50个renderer textures（12图稿、24纸纹、12阴影、2光场），切换及循环交互UUID和数量稳定；dispose释放两种法线。Vite忽略artifacts监视，避免Windows下载锁致EBUSY。

## 运行与部署

React19、Three0.185、Vite8；npm run dev默认4173，npm run build生成本地dist，无自动发布。单元测试、图稿验收、browser及rapid-hover报告见docs/validation.md与artifacts/region-stamps/。Chrome/Playwright覆盖桌面和320/390像素宽移动视口；没有低端真机性能测试。

## 证据与未核实项

2026-10-28报告验证三组筛选、12票素材、暖光命中、背景像素静止、聚焦、键盘/触摸、资源循环和回退。主流程实现见src/；完整数据和限制见docs/architecture.md及docs/region-stamps.md。地标作为AI图像中的视觉元素未做地理/建筑精确性校验。
