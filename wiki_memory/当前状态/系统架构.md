# 系统架构

## 模块职责与边界

根原八态版保持。地域App管理分类、邮票参数和独立相框参数；StampGallery仍拥有唯一Renderer、Canvas与按需RAF。ArtFrame负责模型/文字、轻透视相机、共同父组微旋转及射线分类，并通过固定实体深度通道、MSAA离屏目标和合成图处理淡出。静止时缓存相框PBR图。

## 数据流与依赖

1. inspect-frame-studio.py只读原blend→data/frame-studio-source.json→FrameStudio的三灯完整坐标/旋转/颜色/功率；保留源世界光0.16及源AgX曝光0.4。
2. EXRLoader/PMREM仅供相框；FrameDiskLight在官方LTC中积分32边圆盘并处理法线/视线平行状态；FrameDisplay用原64³LUT输出。FrameContactShadow在源Backdrop位置作同灯位确定性墙影。
3. FrameParameterPanel→独立规范化参数→configureFrame→灯具/材质/显示Uniform与缓存失效。模型存储key postal-studies:frame-studio:v1，与邮票参数分离。
4. 指针更新相框共同父组；原三组文字Raycaster→React分类→右侧四枚邮票。材质、纹理和模型在分类/聚焦期间复用，结束释放离屏目标与既有资源。
5. 相框合成后恢复Renderer目标、颜色、曝光和视口，再绘制原邮票Shader。外部页面底色不接入HDRI或动态光场。

## 运行与部署

runGo=地域4174，runStart=原版4173，共享根node_modules、按origin隔离存储。没有改CMD、锁文件或启动器。Blender实际F:/Blender/blender.exe。当前脚本verify-frame-studio、verify-art-frame、verify-light-presets与verify-frame-production分别验证相框、整页、六算法与构建产物；生产冒烟的临时端口已关闭。

## 证据与未核实项

2026-10-29的25+14+19+8+1+19项与两版build通过。真实GPU源值、位姿和像素证据见sources。32边LTC和外轮廓墙影是实时近似，不包含Cycles全部自遮挡与路径追踪GI。
