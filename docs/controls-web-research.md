# 参数面板增补：参考网站重新实测

实测日期：2026-10-26。用本机 Chrome / Playwright，1440×900 CSS px，对 [Bill Guo](https://billguo.me/) 的画廊和聚焦态移动真实鼠标，再读取公开 DOM / computed style；对 [Microsoft AI](https://microsoft.ai/) 的 WebGL uniform 调用作只读观测。没有修改两个远端网站的持久状态，也没有复制其素材或 Shader 到工程。

复现脚本：[research-controls-web.mjs](../scripts/research-controls-web.mjs)。本轮原始证据：[web-parameters.json](../artifacts/controls-research/web-parameters.json)。这份文件记录原站，不应与本地工程参数 JSON 混用。

## 聚焦之后：原站的“朝指针微偏转”

这次原站详情图片成功载入，`naturalWidth=431`，可以直接查看最终材质。此前研究记录中的空白详情属于当时的图片交接/加载状态，本次结果补足了该限制。截图：[原站聚焦右上悬停](../artifacts/controls-research/bill-focused-upper-right.png)。

1440×900 窗口里，聚焦卡片未偏转时 `431.21875×540px`，左上 `(499.390625,180)`。页面保留10px滚动条，所以相对1430px可用宽度居中。其 `figure` 给子元素提供 **1400px 的 CSS perspective**；`paper` 子元素独立做 `rotateX / rotateY`。

令 `u/v` 为卡片未偏转矩形中的位置，左上为 `(0,0)`，右下为 `(1,1)`。稳定后测得：

| 指针位置 | CSS rotateX | CSS rotateY | 外层 figure |
| --- | ---: | ---: | --- |
| 中心 (.5,.5) | 0° | 0° | identity |
| 左 (.12,.5) | 0° | −4.5595° | identity |
| 右 (.88,.5) | 0° | +4.5593° | identity |
| 上 (.5,.12) | +4.5596° | 约0° | identity |
| 下 (.5,.88) | −4.5593° | 约0° | identity |
| 右上 (.82,.18) | +3.8394° | +3.8397° | identity |

这些测量支持约 `rx = −(v−.5)×12°`、`ry = (u−.5)×12°`，即每个方向从中心到边缘约 **6°**。这是从实测反推出的响应关系，并非宣称取得了生产代码中的参数命名。

坐标转换需要留意：CSS 的 y 向下，Three.js 的世界 y 向上。若使用本项目 `vUv.y` 向上的 UV，匹配原站需要 Three `rotation.x = −(uv.y−.5)×12°`，而 `rotation.y = (uv.x−.5)×12°`。修改前本地 X 轴正号与原站相反。

透视能解释“已有转角但观感仍较平”的差异：在原站上方指针点，投影包围盒变为约 `437.93×538.42px`，上下边存在远近关系。单纯正交相机转动一张平面只会产生余弦压缩，不会产生这种近大远小。角度和透视距离需要分别调节。

本次还确认了离开卡片后的行为：先在右上停留，然后依次把指针放到卡片右/左/上/下外部，每处停留600ms，`paper` 均保持 `(3.84°,3.84°)`，外层 `figure` 一直是 identity。原站此状态保留最后姿态，不会继续追踪全窗口，也不会立刻回正。面板用“移出保留 / 回正”区分这两种体验比仅增大角度更有用。

连续 rAF 采样中心→右上阶跃，角度最终为3.84°：

| 达到最终角度的比例 | 距 pointermove 事件约 |
| --- | ---: |
| 50% | 78ms |
| 63.2% | 106ms |
| 90% | 195ms |
| 95% | 236ms |
| 99% | 335ms |

这是一次本机采样的响应时间，不能把335ms误读成固定动画时长。它先加速再收敛，适合用两级短时间常数或临界阻尼弹簧逼近。修改前本地 pointer / tilt 各有0.12秒阻尼，两级叠加会比上表更滞后。

另外，原站支持按下拖动：一次指针向右107.8px、向上81px，外层 `figure` 实测平移约 `(35.93,−67.5)`；松开后回中心。这是独立的拖拽交互，不能用它来推断普通悬停时的位移或旋转。当前用户指出的方向偏转主要对应上表的子元素倾斜。

## 画廊悬停

原站画廊 `wrapper` 的 perspective 为 **1200px**，聚焦为1400px。当前邮票 `paper` 的 scale 收敛至 **1.05**；其余邮票主要通过4px模糊退后（旧轮 CSS 观测），没有统一降低透明度。画廊也有 rotateX/Y：本次上/下位置测得约+4.0°/−4.4°，左/右约−4.5°/+4.0°；因外层还持续轻微漂移、测试点以初始包围盒定位，这组坐标不如聚焦态精确，不应当成严格对称上限。总体支持边缘6°附近的克制幅度。

[原站画廊右上悬停截图](../artifacts/controls-research/bill-gallery-upper-right.png)。原站底层浮动、局部压纹光照和全局物体倾斜是三个层次，仅调亮度无法互相替代。

原站的 NCS 纸面有密集地形纹理，局部亮部同时影响细线/压纹观感；本地是独立绘制的 Canvas 印刷纹理，加斑驳光明暗和轻微纸面高光。即使把倾角、速度、光色调成同值，细节材质也不会完全一致。面板能解决可调数值和交互节奏的差异，不能把两张不同图稿自动变成同一张图。

## Microsoft：必须按 pass 读取参数

实际截图：[Microsoft 首页](../artifacts/controls-research/microsoft-current.png)。一个720×450 WebGL2缓冲放大到1440×900 CSS，依次包含底色、椭圆光域、正弦位移、Voronoi变形、柔焦、最终合成等程序。它是全屏斑驳光参考；依照用户后来纠正，本工程仍把这种光限制在邮票表面。

**多个程序使用同名 `uPos`、`uAmount`、`uSkew`。** 单凭最后一次同名 uniform 调用会得出错误结论；证据脚本改为按 WebGLProgram 分组。实测如下：

| 层 | 本轮实际 uniform | 可以指导的控件 |
| --- | --- | --- |
| 椭圆光域 | radius .354 / falloff 1 / skew .54 / angle 0 / displace 0 | 范围、边缘衰减、光域形状 |
| 正弦位移 | frequency .35 / amplitude 1.18 / rotation 0 / trackMouse 0 | 波浪幅度、运动速度 |
| Voronoi变形 | amount .534 / spread 1 / skew .84 / angle 44/360 | 光斑密度、拉伸、方向、散射 |
| 柔焦 | amount .754 / tilt .5 / blueNoiseResolution 256×256 | 散焦、细颗粒 |
| 合成 | base #ffaaa5 / vignette #4a0035 / light #ffd198 | 底色、阴影色、暖光色 |

表中 .534 与 .754 来自不同 pass；44/360 是原站归一化角度，不能直接当本地弧度。原站参数与幽兰/本地控件只是功能映射，并非同名值可原样互换。

鼠标追踪已取得直接证据：将指针依次移到左 `(100,450)`、右 `(1300,450)`、上 `(720,100)`、下 `(720,800)`，椭圆光域程序的 `uPos` 分别收敛到：

- `(.069445,.500001)`
- `(.902777,.500000)`
- `(.500001,.888888)`
- `(.500000,.111112)`

这与浏览器归一化指针及Y反向对应，证明**光域本身跟随指针**。正弦位移程序的 `uTrackMouse=0` 只说明该 pass 不跟随，不能推断整个首页光效不跟随。其余变形和柔焦程序的 `uPos` 保持(.5,.5)，时间变量仍变化。

## 对本轮控件设计的建议

优先把四组独立因素暴露出来：悬停抬升/缩放/旁票模糊；聚焦尺寸/进入退出时长/倾角/透视/移出行为；邮票光强/对比/色温/光域/散焦/密度/方向/拉伸/波浪；指针影响/阻尼/时间流动。悬停和聚焦角度应分别可调，便于用户先固定一个状态比对。

建议原站交互起点为画廊1.05缩放、倾角边缘6°、perspective1200px；聚焦边缘6°、perspective1400px、移出保留姿态。光影从现有暖纸预设起调，避免把全屏桃粉光色原封不动覆盖到绿色邮票上。原站/幽兰/Microsoft 的具体单位和渲染面积不同，预设应标注“参考”而非“逐项复制”。
